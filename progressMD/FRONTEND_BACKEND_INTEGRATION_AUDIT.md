**Audit Date:** 2026-10-16

## 1. Page-by-Page Integration Analysis

### 1.1 `OrdersPage.tsx`
- **Route:** `/orders`
- **Endpoints Called:**
  - `GET /api/orders/lifecycle/queued?limit=100`: Reads queued items.
  - `GET /api/orders/lifecycle/running`: Reads executing orders.
  - `GET /api/orders/lifecycle/done?limit=100`: Reads completed orders history.
  - `POST /api/orders/`: Creates a manual order.
  - `POST /api/orders/lifecycle/run-next?scenario={scenario}`: Runs next queued order.
  - `POST /api/orders/lifecycle/run-order/{order_id}?scenario={scenario}`: Runs specific order.
- **Integration Gaps Found:**
  - `POST /api/orders/` does not pass an `idempotency_key` header or field, exposing the form to double-click duplicate creation.
  - Endpoints `/api/orders/lifecycle/*` were wired to `OrderLifecycleService`, which bypassed `GovernedOrchestrator` and generated synthetic mock decisions.
  - `order_processing_queue` (Migration 013) metrics (`/api/orders/queue/status`) were disconnected from this page.
- **Remediation:**
  - Wire `OrderCreateRequest` to include `idempotency_key`.
  - Connect order execution directly to `GovernedOrchestrator`.
  - Disable button during active execution to prevent double submission.

### 1.2 `OrchestrationPage.tsx`
- **Route:** `/orchestration`
- **Endpoints Called:**
  - `GET /api/orders/lifecycle/queued`
  - `GET /api/orders/lifecycle/running`
  - `GET /api/orders/lifecycle/done`
  - `GET /api/orders/lifecycle/decisions?order_id={id}`
  - `POST /api/orders/lifecycle/run-next`
  - `POST /api/orders/lifecycle/run-order/{id}`
- **Integration Gaps Found:**
  - The decision logs displayed came from `agent_decision_logs` generated by the synthetic mock runner rather than actual `agent_runs` from `GovernedOrchestrator`.
- **Remediation:**
  - Unify `agent_decision_logs` so they reflect actual runs of `SupervisorAgent`, `InventoryAgent`, `ProcurementAgent`, `FinanceAgent`, and `LogisticsAgent`.

### 1.3 `ExceptionsPage.tsx`
- **Route:** `/exceptions`
- **Endpoints Called:**
  - `GET /api/exceptions/`: Fetches exceptions list.
  - `POST /api/exceptions/{id}/resolve`: Resolves an exception by executing its proposed action.
  - `POST /api/exceptions/{id}/resume`: Resumes the order to queue.
- **Integration Status:**
  - Calls real backend endpoints in `backend/app/api/exceptions.py`.
  - Gap: `resume_order_from_exception` previously reset orders to `QUEUED` without verifying whether the exception was actually fixable, causing an infinite retry loop.

### 1.4 `AuditTrailPage.tsx`
- **Route:** `/audit`
- **Endpoints Called:**
  - `GET /api/audit/events`: Fetches real immutable `event_log` entries.
  - `GET /api/audit/blockchain/anchors`: Fetches blockchain anchor records.
  - `GET /api/orders/lifecycle/blockchain/blocks`: Was displaying synthetic blocks.
- **Integration Status:**
  - Real event log is properly grounded in SHA-256 payload hashes.
  - Blockchain blocks tab should display verified blockchain anchors from `blockchain_anchors` and smart contract event receipts.
